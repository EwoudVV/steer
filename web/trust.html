steer / faking time

What steer checks, what it catches, and what it doesn't. Written for fraud squad and program reviewers, but anyone can read it. The code for all of it is at github.com/EwoudVV/steer.

What steer trusts

  • When things happened. The server stamps every event when it arrives. An event more than 5 minutes off from that doesn't count, so old logs can't be sent in later and times can't be moved around.
  • That the person did something. Time only comes from things a person does: a prompt, stopping the agent, a code change while the agent wasn't editing, a commit. The agent running by itself never counts, and code changes and commits only count within 30 minutes of using an AI tool, since coding without one is Hackatime's job.
  • Nothing about the prompt text. Prompt text never leaves the person's computer, so there's nothing to fake there either. Only counts are sent, like how many words a prompt had.

What's checked

TrickWhat happens
Sending lots of prompts at once, or pasting long prompts fastA prompt never counts more than the time since the person's last action.
Running several sessions or agents at onceTime that overlaps is counted once.
Typing "continue" or "fix it" over and over without testingShort prompts count at most 2 minutes. 3 or more in a row without testing count only the typing, at most 30 seconds each.
Walking away and coming back hours laterAny gap over 30 minutes is a break: 2 minutes to catch up, 5 if the person tested something, plus typing.
Leaving it running all dayAt most 12 hours a day and 60 a week count. A day over 12 hours, any 24 hours over 14 (so midnight doesn't hide it), and more than 8 hours with no break longer than 20 minutes all get pointed out.
Saving a file over and overOn the person's computer a save only counts if the contents changed, the agent wasn't editing, and the files aren't back to how they were in the last hour. The server can't check that, so saves and commands only count within 30 minutes of something from an AI tool, only the first minute before each one counts in full, and a day where most of the time came from them gets pointed out.
Making up commitsEach commit on a review page is looked up on GitHub. A commit that isn't there, or was made at a different time than steer saw, is marked in red, and the page shows who made each one on GitHub, so commits from someone else's repo stand out.
Stopping an agent that isn't doing anything, over and overCounts 5 seconds each.
A new session for every prompt, so each one counts as typingMore than 2 hours a day counted just from typing gets pointed out.
A script that prompts the agent the moment it stopsPointed out: "replies usually came 8s after the agent stopped".
A script with a steady rhythmPointed out: "prompts came at very even intervals", and long days without a break.
Agents prompting each other in T3 Code, which the agent's own log shows as the person typingPrompts from T3 Code are looked up in T3's database on the person's computer, and only the ones the person wrote count. Without that database, Claude Code prompts from T3 don't count at all.
Prompts the agent never answeredOnly typing counts, and a day with lots of them gets pointed out.

The pointed out ones show up under Checks on the person's page and on every review page. They aren't automatic bans, since most have honest reasons, like a long hackathon day.

What it doesn't catch

steer can't stop someone who writes their own program to send made-up events with their own key, if the events look like a real person working: uneven gaps, breaks, nights off. We had AI agents try to fake time on 2026-11-22: the best script that copied a real rhythm with prompts got about 4 to 6 hours a day counted without any of the checks pointing at it. Every trick that got more than that now gets pointed out, or counts nothing. The same goes for any tracker that runs on the person's computer, Hackatime included.

What gives it away is the project. Made-up hours don't come with code. So on a review page, look at:

  • the commits, and whether GitHub has them at the times steer saw
  • whether the hours fit what the project is
  • days with lots of prompts and no code changes or commits at all

A script can also make real code changes and real commits. Those end up in the project's history, where they can be seen.

How the counting was picked

Thousands of days of work by different kinds of people (focused, multitasking, careful, mostly prompting) were simulated, matched to real logs. Every counting rule counted the same days and was compared to the real time. The rule steer uses came closest for every kind of person: within about 10 to 15% normally, and 22% in the worst case of everything that was tried. A flat 1/3 of agent time was off by up to 182%. The simulation is tools/sim/simulate.mjs in the repo.

For reviewers

  • Every submitted project has a review page that never changes after it's made, with a written justification and every action behind the hours.
  • Every event behind a review page, with when the server got it, is at /api/r/ID/events.
  • Everything steer has for a person, by Slack id: /api/slack/SLACK_ID. All of an account's events: /api/u/NAME/events.
  • Fraud squad and program reviewers can sign in on a review page with Hack Club to approve, cut or reject the hours, with a note the person sees. Ask duck to be added.
